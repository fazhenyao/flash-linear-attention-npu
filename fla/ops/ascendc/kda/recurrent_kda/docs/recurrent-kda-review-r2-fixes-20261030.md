# Recurrent KDA 二轮检视整改与分路径复测（2026-10-30）

本轮修复 PR #997 的四项确认问题：原位独立 finalState 复制、活跃 State 元数据值校验、safe gate 的 NaN 漏检、A5 编排结构。公开 ABI、CPU 标杆、输入生成值域与精度标准保持。用户冻结的 `recurrent-kda-a5-regbase-redesign-20261026.md` 未修改，其 SHA256 为 `78f03d56724f4ff6ba36609f1f53dbc05148825b94ee7d253a7867c8c331d5b4`。

## 版本与实现

- 整改前：`ede1185b66f2fd5502167421e3154073a0f324f7`。
- 远程 main：`2bb7e74ecf4876acbc4527070e403bffeef06e75`，采集前后核对未变化；使用此前从完整该提交实际构建、安装并审计的隔离包，复用前再次核对全部78个so/o哈希。
- 整改后：以整改前提交为父提交的本次代码。实际构建源码与当前21个实现/配置/回归文件核对通过，文本只规整UTF-8 BOM与CRLF/LF；源文件原始哈希另存。runtime Python 源码与安装包文本核对通过。

| 检视项 | 修改与证据 |
| --- | --- |
| 原位更新另传独立 finalState | `CopyStateView` 统一逻辑范围和 plain format 标签，保留目标 offset/外层 stride；非原位初始化与原位独立输出共用 helper。直接 ACLNN 新增两布局×两dtype×连续/带间隔共8项，全部通过。 |
| 非法索引/accepted 静默退出 | 在 ACLNN 第一阶段校验活跃 slot、accepted 范围及 speculative 长度；错误含请求、token、actual、capacity/length，返回161002。空请求与 padding 不读取原元数据。executor 保存校验后的 host 快照并交给 kernel，关闭该路径缓存，避免消费旧值。 |
| safe gate 的 NaN lower_bound | ACLNN 与 tiling 都使用有效区间的否定表达式，拒绝 NaN/±Inf；未传 A_log 时仍按契约忽略相关参数。三入口负向回归通过。 |
| A5 context/Stage 结构 | `recurrent_kda_struct.h` 保存纯数据 context 和布局常量；`recurrent_kda_vec.h` 保存 VF 启动/计算；`recurrent_kda_pipeline.h` 使用文件作用域 Stage/编排函数并补齐 Stage、UB 布局、同步协议表。30个原方法的可执行 token 经标识符和context映射逐项一致；不改变算术、bank/token顺序、必要同步及整tile out批量搬出。 |

活跃 indices/accepted 的 device→host 校验需要一次设备同步及D2H，与已有CU快照共享必要同步；每个活跃请求复制相应元数据切片。没有 indices 的模型调用不增加该步骤。索引模式不可在ACLGraph捕获中调用，元数据变更须重建executor；快照的host内存、复制及后续上传成本不能由kernel耗时代表。此修复适用于共用host入口，A2/A3未上板验证。
