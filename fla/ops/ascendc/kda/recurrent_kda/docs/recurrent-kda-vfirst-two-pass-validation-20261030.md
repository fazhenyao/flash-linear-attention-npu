# V-first State两遍读取验证

2026-10-30，方案规则V2。用户确认验证V-first两遍State读取，基线为已验收kbf30；受保护原方案不修改。仅实验arch35的V-first FP32/BF16，接口、CPU标杆、输入值域、混合容差和K-first两遍计算保留。

## 候选v2r33

第一遍沿V行连续读取原State，寄存器转换为FP32，按原64+64归约树计算`prediction[v]=Σ_k State[v,k]*(alpha[k]*k[k])`。prediction按四行收集到两个64元素寄存器，再计算128个`delta=v-prediction`。第一遍只读State，不保留State矩阵或修改任一bank。

第二遍重新连续读取同一源bank，计算`State_next=alpha*State+delta*(beta*k)`，使用未舍入的FP32更新值计算out，随后以接口dtype写另一bank。沿用beta*k预计算和State MulAddDst，out仍在寄存器收集，完整tile后批量搬出。

为使两遍读取实验不混入上一轮已验证低效的v寄存器Gather/轮换，优先将delta写到原vFloat的512B临时区（`eventOffset+256`起），仍是两次FP32 VST和同一专用VST→VLD屏障，第二遍沿用原UB标量广播。该区原有v在本候选不写入，delta从生产后存活到本token最后一行更新消费完，下一token才覆盖；前36B事件字不重叠。第一遍prediction寄存器在Sub后释放。不得在UB保存FP32 State影子。

所有输入、GM流量、UB峰值、任务映射、两个递推bank及可用第三bank预取、必要State/out同步、快照等待和尾部排空保持原规则。State有效UB读量FP32 64→128KiB/token、BF16 32→64KiB/token，写量仍64/32KiB；BF16每次Load后转FP32、Store前Cast_RINT。一个Vector Stage内顺序执行两遍，不增加workspace或跨Stage事件。

数值门禁：alpha*k先乘再参与点积，相对原先State*alpha再乘k存在FP32舍入变化；无新增高风险非线性运算，有限输入范围和既有gate/归一化保护不变。按原CPU标杆与混合容差验收，不要求与kbf30逐位一致。BF16 out必须使用未舍入State结果。

收益假设是缩短prediction期间State的寄存器生命周期、减少同时活跃的State和乘积，分离预测与递推两段依赖。它不会消除V-first的逐行归约，且增加State Load/Cast和prediction收集，不能静态认定更快。必须核对完整动态指令和同卡msprof计时。

标准run构建安装、72对象和源码/跨机二进制身份核对，132原有+54对齐精度，随后用A5_ci空闲健康物理卡7同卡串行对比issue680 ID0/2/3/7/20/35×两State dtype共12组。目标kernel为RecurrentKda，msprof Task Duration，每例3预热+5正式样本，按正式5样本均值及耗时比几何均值判定，收益须超过噪声、典型长短例无不可接受回退。每轮重新采基线，不替换样本。精度及正常启动在A5_1物理卡6。

## 最终结果：采用v2r34，X=1保持单遍

v2r33对所有V-first调用使用两遍读取，典型12组合先验证为FP32 -8.76%、BF16 -6.46%，但全模型发现单token回退。完整首轮FP32为-4.98%（25/36均值更低）、BF16为-6.96%（35/36），最大回退分别7.75%/2.00%。因此没有直接采用全范围两遍方案，也未把典型收益当成全模型结论。完整首轮数据保留。

v2r34采用统一规则：**X=1使用原有单遍，X>1使用两遍State读取**。在VF外选取内部模板，保留原fused/general选择，不改变公开TilingKey。变长调用由最大请求长度选公共X；X>1下的短请求或1-token尾tile仍走两遍，不额外引入VF内判断。BF16部分单token小形状在首轮也有收益，但为避免大State短序列回退，本轮统一保留X=1原路径。

基线为本轮开始的已验收kbf30，同卡重新采集；不是远程main或跨卡历史数据。性能为A5_ci物理卡7/逻辑0，精度/契约/确定性/原生内存探针/正常诊断在A5_1物理卡6/逻辑0；Ascend950PR、CANN 9.2.0-beta.2、Python 3.11.17、torch 2.9.0+cpu/torch_npu 2.9.0.post6。机器共享，逐例前后npu-smi占用快照保留。

## 精度、内存与身份验证

v2r33和v2r34各完成标准run构建安装、libcust_opapi MD5、72对象JSON/build核对，132原有+54对齐精度、74公开契约、9确定性（每项3次）均通过，CPU标杆、值域和混合容差未改。两版各18实现/调用源文件审计一致，每轮基线+候选156项so/o跨A5_1/A5_ci SHA256一致，候选78个已安装so/o与封装包一致。最后源码与v2r34快照一致；下载zip逐文件校验大小和SHA256。

两版各在FP32/BF16×最终State/逐token快照4组当前Pipeline原生mssanitizer探针通过，均No error detected、out/State探针对比通过。每组4连续任务、T9、X8，覆盖跨tile、bank复用及第三bank预取，对应追踪版完成49/157条记录并HOST_FINALIZED。v2r34另外通过两dtype X1/T1/逐token快照的2组memcheck，验证新增单遍选择。入口是-O3、启用sanitizer的state_pipeline_probe，不是正式RecurrentKda包的mssanitizer报告。

小规模正常启动两候选的BF16 out/State均与kbf30逐位一致；FP32 out一致，FP32 State最大绝对差约5.59e-9。此为该输入的数值对照，不替代CPU精度验收；alpha*k乘法重排不要求普遍逐位一致。State在UB仍只有接口dtype，BF16 out在State写回舍入前计算，整tile完成后批量搬出保持原规则。

第一遍prediction与第二遍更新/out分离，移除了每行prediction广播与Sub，改为128个delta一次形成后供第二遍广播；State不再跨prediction归约存活。BF16探针同配置编译报告单遍VF为30个VReg、两遍为26，栈均0B；这是生产Pipeline探针的编译证据，不冒充正式包VF的资源报告，也不能套用occupancy解释。

收益伴随更高UB读取和BF16转换开销：v2r33的BF16总事件比基线增加16.69%，仿真区间仍降低约6.2%；FP32转换负担较小。逐行prediction/out的VCADD数量不变，不能声称消除了V-first归约。代码依赖和寄存器报告支持生命周期及调度改善的解释，未完成逐周期停顿分解，不能把全部收益归因于单一指令。必要State/out同步、scratch写读屏障、快照等待与尾部排空保留。

最终v2r34在X>1的State有效UB读量为FP32 128KiB/token、BF16 64KiB/token，写量仍64/32KiB；X=1保留原64/32KiB单遍读取。GM流量与UB峰值不增加，512B scratch由v改为delta。没有新增FP32 State影子。

静态issue覆盖188项通过；仍有当轮114项host DFX-MESSAGE发现，两个修改kernel头文件无发现。A2/A3未上板。受保护原方案SHA256未改；本独立补充与docs/design.md已同步采用的实现。
