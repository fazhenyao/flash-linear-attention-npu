# K-first UB 行距优化记录

本轮由用户授权调整 State 的 UB 物理排布，解决 subbank 冲突。接口和 CPU 标杆不变；受保护的寄存器方案文件保持原样。本记录是该方案的局部实现补充。

## 设计

采用 CHUNK_DEPENDENT/V1 开发参考（a14961e9dfe8c8264768d67fb447101873da4ecf）的状态依赖、producer/consumer 生命周期和覆盖前等待方法；计算仍为一个 Vector Stage，没有跨核 workspace。

只改变 A5 K-first 的 UB 物理行距，GM 的 shape、stride、dtype 和 K-first 布局不变。FP32 的行距由128改为136个元素（544B），BF16 由128改为144个元素（288B）。每行有效128个元素，行末额外32B；MTE2 用二维搬运插入行间空隙，MTE3 用二维搬运跳过空隙。每行的 DMA gap 都是一个32B单元，输入与输出分别保留原有 GM stride。

Gather/Scatter 的 lane 索引、后半 K 区起点采用 UB pitch；四个 V 行计算和归约维度仍为128。BF16 保留32位成对读写及寄存器 Cast，不增加 UB FP32 State 副本。padding 不参与计算、不写入 GM，也不需要初始化。

FP32 K-first 每 bank 由64增至68KiB，三个 bank 共增加12KiB；BF16 的36KiB有效含 padding 数据仍放在原64KiB bank 中。host 预算只在 A5 FP32 K-first 增加12288B，X=8时237120B，低于248KiB上限。V-first 保留原64KiB bank、全部输入/out偏移及连续读写；入口按布局分派编译期模板，避免在其热路径增加动态 pitch 运算。A2/A3 不采用新布局。

两个 bank 交替递推、第三个可用 bank 预取、快照源 DMA 完成前不得覆盖、tile 完成后批量搬出 out 等同步和生命周期不变。初态预取、逐 token 快照、最终状态使用相同 pitch 映射。

## 验证计划

在 A5_1 独立目录构建 run 包，核对实际加载产物。正式 CPU 精度回归包含两种 State dtype、两种布局、快照、非连续 GM State、空请求、跨 tile 和 X=1/2/4/8。性能用 msprof Task Duration，在同卡同环境比较优化前后；每例3次预热、5次采样。仿真使用新旧正式 kernel 的单 AIV 短请求，比较 Gather/Scatter 延迟，仿真数据仅用于归因。

## 结果

构建与测试在 A5_1（<remote-host>）进行，CANN 9.2.0-beta.2，Python 3.11.17、torch 2.9.0+cpu、torch_npu 2.9.0.post6；真机计时使用健康的 Ascend950PR 物理卡7、逻辑卡0。系统有其他用户常驻进程，采集前后卡7利用率为0%，不宣称独占环境。最初尝试卡6时其他任务占满设备，该次未形成性能对比数据。

标准命令为 `bash build.sh --soc=ascend950 --pkg --vendor_name=fla_npu --ops=recurrent_kda -j12`。系统 OPP vendors 目录对当前用户不可读，构建通过任务独立的 OPP 配置目录完成；built-in 保留系统文件。因 build.sh 会重新加载 CANN 环境，编译子 shell 用 BASH_ENV 恢复该配置。真机测试仍用系统原始 ASCEND_OPP_PATH。未修改 CANN 安装或系统权限。

以独立 venv 安装 run 包，opapi MD5 与新构建一致；72个已安装 kernel .o 逐一与构建目录及对应 JSON 的 SHA256 比较一致。构建输入1857个文件与源清单匹配。实现基线为本轮修改前、已完成方案对齐的版本，复用 A5_1 上冻结的 packages/current；不混入远程主线或更早“可接受实现”的结果。

### 真机模型性能

使用 msprof --task-time=on，筛选 op_summary 的 RecurrentKda / Task Duration(us)，按设备时间顺序每8次调用一组，排除3次预热，取最后5次均值。每版84个 case、672个目标 task；包含 issue680 全36组形状 × FP32/BF16 K-first，加上 ID0/1/2/3/7/35 × FP32/BF16 V-first 共12个回归 case。两版 manifest 的输入 shape/stride/dtype、属性及种子逐项一致；每次均为56个 block。输入生成、ViewCopy、有限值检查及 host 调用时间不计入目标 kernel 耗时。

QKV/out 为 BF16，g/beta/A_log/dt_bias 为 FP32；packed TND、融合 QKV view，QK归一化/raw gate/beta sigmoid 开启，原位更新并返回 final State，无 indices、safe_gate=false；种子20261020。按最大请求长度选择 X=1/2/4/8。

### 指令仿真

用本轮正式 run 包的 .o 与冻结旧版 .o，通过原生 ACL 二进制接口各启动一个 AIV、H=HV=1、T=1、X=1。输入为有限常量，并在返回后检查 out 与 State。六个最终采集（两版 × FP32 K-first、BF16 K-first、FP32 V-first）均输出 HOST_FINALIZED；不同 dtype 选择对应正式二进制。未使用诊断探针替代正式 kernel 计算体。

| 指标 | FP32旧 | FP32新 | BF16旧 | BF16新 |
| --- | --- | --- | --- | --- |
| 首条 State Gather 至最后 Scatter 完成（μs） | 20.260 | 5.213 | 10.180 | 3.232 |
| Gather 中位数（ns） | 258.8 | 71.5 | 212.1 | 49.1 |
| Scatter 中位数（ns） | 386.1 | 81.8 | 143.0 | 66.7 |
| Gather / Scatter 数量 | 256 / 256 | 256 / 256 | 128 / 128 | 128 / 128 |
| 完整诊断 kernel（μs） | 26.124 | 13.273 | 14.623 | 9.465 |

访问次数没有减少，显著改善来自每条离散访问的耗时下降。该32B行间空隙使64个 lane 分布到16个硬件 bank：FP32 从同一 bank/subbank 的64个地址变为每 bank 4个；BF16 成对访问从2个 bank 分布到16个。因此是大幅缓解集中冲突，不宣称所有 subbank 冲突归零。更小的非32B对齐行距需要另外的装载/重排设计，本轮不采用。

V-first 完整短请求仿真由7.259增至9.225 μs，说明不能仅凭其 UB 布局不变就断言全部入口开销不变。本轮新增布局模板分派；该约1.97 μs差额未做独立指令级根因定论。生产模型已按上节验证，没有把短请求的仿真差异替代真机模型结论。

早期 BF16 仿真出现过主机检查脚本 dtype 转换错误，以及一次 simulator 的 VM 寄存器解析异常。修正检查脚本后重新采集，表格只使用最终完整成功记录；旧的 OPPROF 目录保留，早期失败不参与该表统计。未运行此前已确认会挂起的真机 PipeTimeline 重放。
