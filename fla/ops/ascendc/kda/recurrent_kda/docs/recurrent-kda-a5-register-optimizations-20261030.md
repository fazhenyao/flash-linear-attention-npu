# RecurrentKda 寄存器指令优化实验（2026-10-30）

基线为已通过完整验证的 Stage16；保留 X=8 V-first 固定窗口特化、BF16 State 的 UB 存储、必要同步与整 tile out 批量搬出。用户原始方案不修改。

## 顺序与判定

1. reg17：仅将 State 更新的八组 Mul+Add 改成 MulAddDst，合并为八条 FMA；每 token 32个四行块，静态预计减少256条 Vector指令。FMA舍入与分离乘加不同，沿用现有精度标准验证。
2. reg18：从相同基线独立验证 beta×k 公共乘积。每 token 先计算两个64列片段，行内只计算 delta×(beta×k)；原始 k 仍用于 prediction，sigmoid_beta 先于公共乘积。静态预计每 token 减少126条乘法，但新增两个常驻寄存器且改变舍入顺序。
3. reg19：研究四个归约结果的收集，保留已积累的全部历史 lane。先核对公开接口与编译指令，不能用直接 Gather 覆盖历史结果。若指令数或时延不降则回退。

每项均先标准构建、72对象审计、132例原有精度与54例对齐精度；通过后使用 A5_1 物理卡4，同卡基线，msprof Task Duration，3次预热+5次正式样本。典型20组覆盖 issue680 ID0/2/3/7/35、两种State布局及FP32/BF16 State。小规模 simulator 只用于动态指令及依赖诊断，不替代真机耗时。最终保留通过验证的最优结果；失败或无收益版本仅保留实验记录。

## 结果

### reg17：MulAddDst

72对象审计、132+54例精度全部通过。典型20组耗时几何均值为基线0.976954；V-first T=8改善约3%～5%，K-first FP32则劣化约0.6%，最终应避免让该布局承担回退。

小规模诊断为B=2/H=HV=1/T=8/K=V=128、BF16 State、V-first、X=8、单AIV两任务，完整覆盖16 token。基线共60392条trace事件，reg17为56296；VMUL从18528降至14432，VADD从8288降至4192，新增4096条VMULA，总净减4096条，符合每token减256条。VCADD=4128和State读写量不变。完整仿真时长35.9424→34.7382 μs；此结果只解释指令，正式性能取真机。

### reg18：beta×k

72对象审计、132+54例精度通过。典型20组耗时几何均值为0.970626；V-first T=8改善3.0%～4.7%，K-first BF16改善2.8%～3.0%，K-first FP32的长请求则劣化0.2%～0.4%。小规模诊断VMUL=16512，较基线减少2016条（每token126条），总事件58376；完整仿真34.9909 μs。

### reg19：MERGING输出收集

已实现四个单lane的MERGING Duplicate替代三次Interleave加一次Move，并保留原Gather轮转。mask在VF入口构造，不在行循环中生成。每块仍为五条主要收集指令；实验目标是缩短归约结果活跃范围和改变重排调度，不预先声称指令数减少。历史lane不在mask中，必须保留。72对象审计和132+54例精度通过。典型20组几何均值0.997119，但布局间存在差别：K-first BF16稳定改善约1.5%，V-first FP32 ID35劣化0.72%，因此不能统一采用。

小规模V-first仿真36.4103 μs，反而慢于基线35.9424。VINTLV减少1536条、用于Move的VSEL减少512条，VDUP增加2048条；收集主体没有净减少指令，入口mask等额外事件使总数60392→60529。这支持只在有真机收益的布局上继续组合实验。

### reg20：组合前两项

V-first和K-first BF16计算公共beta×k并使用MulAddDst；K-first FP32保留原乘加顺序，编译期消除未启用公共乘积。out仍采用基线收集方式。




### reg21：仅K-first BF16启用MERGING收集

在reg20上，只对K-first BF16使用reg19的输出收集；V-first与K-first FP32继续使用原Interleave/Move/Gather路径。每token仍仅在完成两个64行半区后Cast/Store完整out，整tile结束后统一MTE3。72对象审计、132+54例精度、74项接口和9项确定性通过。但组合后K-first BF16额外改善仅约0.1%，没有稳定收益，最终回退到reg20。V-first编译对象也发生变化，不能把reg21仿真当成reg20的证据。

## 最终保留：reg20

V-first和K-first BF16先按既有规则完成k归一化、beta sigmoid和allow_neg_eigval，再每token计算两个64列的`updateKey=beta*k`，四行块内执行`MulAddDst(state, v-prediction, updateKey)`。prediction仍使用原k，out仍在State转BF16之前计算；K-first FP32保留原乘加路径。该重排改变FP32舍入，CPU标杆和精度阈值保持原样。

本地两个头文件与reg20已构建源码仅差一处空白行的行末空格清理，计算代码一致。标准run安装、libcust_opapi MD5核对、72对象审计、132例原有精度、54例对齐精度、74项公开接口和9项确定性通过。本轮未改地址、State/out布局、同步及预取，未重复原生mssanitizer，不能声称完成了新的内存检查。A2/A3未上板测试，本轮代码仅修改arch35。

### 最终动态指令
