# RecurrentKda 四条路径的指令交错调度优化

2026-10-30。用户要求按顺序尝试双发调度，并分别优化 V-first BF16、V-first FP32、K-first BF16、K-first FP32；允许与其他任务共享设备。生产源码及本任务隔离环境的标准安装已选择 vuf43，基线为已验收 v2r34。原寄存器方案未修改。

## 采用的实现

- **V-first BF16，X>1第一遍**：两行独立的低片段Load先进入队列，再分别Cast和Mul；高片段同样成对加载和转换，两个点积FMA、归约交错。只同时处理两行State，之后处理后两行；每四个归约结果继续使用原Interleave/Move/Gather收集。
- **V-first FP32，X>1第二遍**：使用滚动双行，两行低片段更新并生成out乘积后提前Store，随后完成高片段更新、点积和Store，缩短State生命周期；再处理后两行。该路径省去BF16特有的转换成本，因此独立选择调度。
- **V-first BF16第二遍、FP32第一遍、X=1，以及K-first两种dtype**：保留基线计算流程。

四行仅继续作为原out收集粒度，未要求同时保存四行State。候选计算分组没有四行限制。FP32算术、FMA和归约顺序不变，512B residual UB传递及其同步保留；State以接口dtype驻留UB，BF16在寄存器Cast。原bank所有权、第三bank预取、UB容量和GM搬运字节数不变；完整token out保留在寄存器，整tile计算结束后批量MTE3搬出。

## 顺序实验

## BF16 V-first完整小规模仿真

两版均为正式包原生对象单次launch，B=2、H=HV=1、每请求T8、K=V128、X8、一个AIV；完整16token、两个VF均执行结束并HOST_FINALIZED。该工作负载用于诊断，模型性能采用上面的原始56 block真机采集。

两版动态RV指令调用数均56454，所有指令种类的调用数逐项相同；VF累计执行周期39343→38597（-1.90%）。完整trace区间由30.692→30.239 μs。trace的ts/dur按Chrome trace时间单位解释，并与指令CSV周期/1650MHz换算交叉核对。流水时间存在重叠，不累加各pipe时长。

该结果支持“通过独立Load/Cast/计算调度缩短关键路径”的解释；没有直接测得发射级双发率，不将执行区间重叠等同双发计数，也不将收益归因于指令数减少。K-first候选没有收益，未额外扩大仿真。
