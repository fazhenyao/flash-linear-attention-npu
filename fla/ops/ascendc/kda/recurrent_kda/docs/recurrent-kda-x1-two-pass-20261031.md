# V-first X=1 两遍 State 读取复验与采用记录

已按用户要求采用：`RecurrentKdaDispatchLayout` 的 X=1 fused/general 分支将 `twoPass=false` 改成 `true`，与 X>1 共用当前两遍 State 读取流程。生产头文件与实测候选逐字一致。第一遍 prediction、512B delta scratch 及屏障、第二遍 State 更新/out 的组织均沿用已存在实现；bank、预取、必要同步、State dtype 和整 tile out 批量搬出规则不变。冻结方案未修改。

历史 v2r33 曾出现 T=1 回退，故 v2r34 保留 X=1 单遍。本次复验的是后续已优化的双行调度，结果不能直接套用到历史版本。

## 基线、环境及方法

源码基于 main `34851b76` 上重放的 PR head `c7af2aaa`，包含 A2/A3 UB 预算修复。设备为 A5_1 物理卡5（逻辑0），CANN 9.2.0-beta.2。候选以标准完整 wheel 构建安装，opapi、Python 包和72个设备对象核对通过。单遍基线使用 r2 已验收安装包，其9个 arch35 源文件与当前改动前逐文件一致；不是把旧包描述为完整 host 代码也与当前 head 一致。

精度使用原132例及54例对齐，共186例，两路输出均通过原 CPU 标杆、值域与混合容差。ATK 退出清理时日志出现 ACL finalize 500000；发生在全部精度报告生成后，保留原日志，未将其描述为无错误退出。后续独立进程的冒烟与 msprof 正常完成。

性能使用 msprof 的 RecurrentKda `Task Duration(us)`，同卡串行采集 issue680 全部36个形状×四条路径，共144组。每版每组3次预热、5次正式，使用5次均值比较，不计构图、Python、其他算子或预热。每版1152条目标 kernel，全部56个 block，输入 shape、选项和 stride 逐组相同。另有先行20组定向采集；以下以完整144组为准。

允许共用设备。完整采集的基线/候选各288次占用快照，其中135/177次有其他进程，查询均成功；最大组内 CV 为2.96%。保留全部样本，不删样、不用复测覆盖原始波动。K-first 和 T>1 为计算路径未改的控制组，其差异不能归为 X=1 改动的收益。
